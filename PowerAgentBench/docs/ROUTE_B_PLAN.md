## 1. 为什么做路线 B，以及保留什么结论

### 1.1 已有证据

仓库公开的 v2 Dev 记录显示：192 局 Pilot 中 170 局成功；V1 的 96 局全部成功。结构审查记录显示，24 个 Dev 中：

- 19 个存在四台 BESS 等功率的均匀解；
- 另外 4 个没有均匀解，但存在单台 BESS 解；
- 另外 1 个同时超出均匀与单台族，但存在零/满功率组合解；
- 24 个全部存在每台仅取 `{-1.5, 0, +1.5}` MW 的粗模板解。

这些物理结果是已有本地审查记录，本方案编制时没有独立重跑隐藏的 v2 完整网络。[R1][R2]

不能把“穷举 81 个粗模板后全部存在解”解释为“一个四查询算法全部成功”。也不能说只要使用多台设备就属于复杂协调：均匀解本身也可能同时使用四台设备。

### 1.2 正确的问题

旧任务已经支持较窄的开发阶段观察：

> 真实潮流反馈可以减少短程电压校正中的错误，特别是过度校正。

路线 B 研究更具体的问题：

> 当简单动作族不足以覆盖任务、需要位置选择和非均匀幅度时，上述反馈收益是否仍然存在？V 与 R 是互补还是收益重叠？信息压缩会不会丢失对安全节点的约束信息？

### 1.3 保留历史

原 v1、v2、192 局 Pilot、两次独立输出预算诊断全部保留。原 Pilot 使用 4096/provider-default 配置，后来的 high/16384 诊断不能补入原 Pilot，不能把两次独立成功写成“提高上限已被证明有效”。[R1][R5]

不要复用旧 run_id，不覆盖旧结果，不更换旧 Test 文件。v3 是显式的新生成分布和新实验版本。

## 2. 固定研究范围

以下内容沿用现有 benchmark 的物理约定。[R1][R4]

| 项目 | 本轮约束 |
|---|---|
| 网络 | `case33bw()`，网络拓扑、线路参数和参考电源设置不变 |
| 控制设备 | 4 个 BESS，pandapower bus index 8、17、24、32 |
| 有功范围 | 每台 `[-1.5, +1.5]` MW |
| 步长 | 0.25 MW |
| 符号 | benchmark 正数为注入/放电；适配层转换成 pandapower storage 的相反符号 |
| 初始任务 | 纯欠压或纯过压；初始同时欠压与过压暂不并入 |
| 成功判据 | 合法动作、锁定潮流收敛、全部应评估节点电压在 `[0.95, 1.05]` pu |
| 热约束 | 延续当前诊断用途，不新增线路热限值作为得分条件 |
| 模型形态 | 托管 API 的工具调用 Agent，无任意 shell / 文件读取 |
| 主实验预算 | 12 turns、V1 最多 4 previews、R1 最多 3 submits；R0 首次提交后终止 |
| 运行设置 | 沿用已验证的新请求配置 high/16384，并完整记录实际参数身份；不混入旧配置 |
| 暂不加入 | SOC、多时段、无功、动态暂态、设备故障、多 Agent、MCP 全量接入 |

pandapower 的普通潮流不自动更新储能 SOC；storage 正功率表示充电。本任务因此只能声称研究“静态有功校正”，不能把它描述为可部署的多时段储能控制器。[E1]

**Recovery 的准确含义：**当前每次候选与提交都从同一冻结快照重评，因此是失败方案的重规划/重提交，不是对已经不可逆作用于实际电网的动作做物理回滚。所有论文描述保持这一边界。

如果发现现有 evaluator 对 NaN、缺失节点或连通性存在错误，修复属于独立的正确性变更：记录版本影响、回归验证并重新冻结，不静默改旧实验得分。

## 3. 用四个“结构类别”，不用四个主观难度等级

使用 `S1–S4`，S 表示 structure，而不是声称越往后 LLM 必然越难。

### 3.1 动作全集与可行集合

令：

```text
G = {-1.50, -1.25, ..., 0, ..., +1.25, +1.50}
A = G^4
|A| = 13^4 = 28,561
```

对场景 x，定义 `F(x)` 为：在冻结的数值评价协议下，合法且成功的动作集合。

所有“可行”“无模板解”的结论均限定于这个离散动作网格、网络快照和数值 evaluator，不是连续 AC 方程的数学全局存在性证明。

### 3.2 三个预定义动作族

**均匀族 U**

```text
U = {(p,p,p,p): p in G}
```

共 13 个，含零动作。

**单台族 S**

```text
S = {a in A: 非零分量不超过一个}
```

共 `1 + 4×12 = 49` 个。

**零/满功率粗模板族 C**

```text
C = {-1.5, 0, +1.5}^4
```

共 81 个，包含混合充放电符号，不只测试“正确方向”。

这三个集合不是简单的相互包含关系。去重后：

```text
|U ∪ S ∪ C| = 131
```

利用整数动作索引 `(-6,...,+6)` 再乘 0.25，可避免缓存键和网格对齐错误。131 是全部不同模板动作的数量，不等于每个场景新增的 PF 次数：初始零动作可能已缓存，独立重放则另计。

### 3.3 互斥分类规则

| 类别 | 必须满足的判定 | 可以作出的解释 |
|---|---|---|
| S1：均匀可解 | `F∩U` 非空 | 某个共同功率档位可以解决 |
| S2：单台选择 | `F∩U` 为空，`F∩S` 非空 | 等功率调节不行，但选择合适单台和幅度可以解决 |
| S3：粗粒度组合 | `F∩U` 与 `F∩S` 均为空，`F∩C` 非空 | 需要超出上述简单族的设备组合，但零/满功率档仍足够 |
| S4：细粒度非均匀组合 | `F∩(U∪S∪C)` 为空，且 `F` 中有已重放的 witness | 所有可行解均超出上述三个动作族 |

S4 保证：至少两台设备非零、不是四台统一功率、至少一台使用非零且非满功率的中间档。

S4 **不保证**：四台都需要中间档、必须同时充放电、必须使用三台以上设备、需要长期规划、对 LLM 必然比 S3 难。任何这些更强结论需要额外认证。

S1 内保留 `all_full_feasible` 标记，区分明显的满功率边界解与其他均匀解。保留所有族的原始覆盖 flags 和可行模板数量，不只保存优先级标签。

按新规则映射既有公开 v2 Dev 覆盖记录，应得到 `S1=19、S2=4、S3=1、S4=0`。这是迁移/分类逻辑回归检查，不是新 v3 结果。[R2][R3]

### 3.4 分类证据要求

“找到一个 witness”只证明存在可行解，不证明需要复杂协调。

声称 S4，必须同时具备：

1. U、S、C 的全部 131 个不同动作已经覆盖；
2. 这些动作都没有成功；
3. 没有将超时、程序异常、未评价动作偷偷当作已证实的物理失败；
4. 至少一个非模板合法动作成功，并从序列化网络独立重放成功；
5. 保存模板定义哈希、动作顺序、每类计数、求解状态、evaluator/环境身份和证据摘要。

对模板动作发生不收敛的情形，保留其数值状态。为避免将数值不稳定误称为物理结构，本轮严格结构认证要求模板评价完成且可判读；有未解决的数值疑点则标为 `structure_unresolved`，不充当 S4 主集样本。可另存诊断队列，但不得声称不存在物理解。

## 4. 物理场景怎么生成

### 4.1 改什么

只改变负荷与 PV 的空间分布、规模和组合。不能靠缩窄电压区间、变更 BESS 容量或减少 Agent 查询次数来同时“加难”。

保留当前 v2 recipe 作为参照候选族；新增支路相关与局部相反功率分布的候选族。先独立确定生成协议，不能看某个 LLM 的失败率再挑 recipe。

建议首轮四类 recipe 等额采样：

| Recipe | 构造方向 | 目的，不是预先保证的结果 |
|---|---|---|
| A：v2 参照 | 当前空间扰动机制 | 保留与已知任务相邻的覆盖 |
| B：支路相关负荷 | 同一电气支路的负荷相关变化，叠加小幅局部扰动 | 避免只存在全网同方向同幅度变化 |
| C：局部 PV 集中 | 少量位置的 PV 集中注入，其他区域保留负荷 | 形成与设备位置有关的幅度选择 |
| D：分区功率反差 | 不同区域分别偏负荷、偏注入，但初始仍为纯欠压/过压 | 寻找校正某处时容易逼近另一处电压边界的状态 |

初始只单侧越限，不意味着校正时不会把原来合格的节点推向相反越限。这正是可研究的约束冲突；是否真的发生由潮流确认。

### 4.2 首轮数值范围

以下是沿现有 v2 数值包络提出的**合成生成默认值**，不是实际配电网负荷/PV分布的统计估计。[R4]

```text
global_load_scale: 0.3–1.5
per_load_multiplier: 0.3–2.5
PV 数量: 0–4
候选 PV bus index: 5–32
单个 PV 有功: 0.1–3.5 MW
负荷 P、Q 使用同一个倍率，保持各原始负荷的功率因数
```

分支相关的生成可采用：

```text
P'_l = P_l × global_scale × group_multiplier × local_jitter
Q'_l = Q_l × global_scale × group_multiplier × local_jitter
```

但最终局部倍率应落在协议规定的包络内，且截断/重采样方法写入协议。不能引入负负荷、非法节点、断网或直接修改 `res_bus` 伪造电压。

支路分组来自实际在役线路拓扑，不用 bus 编号差作为电气距离。group 定义和参数采样分布必须可复现。

首轮使用独立已保存的 seed。后续若调整 recipe，只能根据物理结构产出、数值稳定性和多样性诊断调整，保留旧协议、候选审计和变更理由。所有新分布在论文中明确作为合成分布报告。

### 4.3 不保证一定生成足够 S4

当前尚无证据证明固定 IEEE33/4 BESS/0.25 MW 下可以高效生成足量、多样的 S4。

因此先完成离线 feasibility gate，再决定数据规模。不能先承诺 32 Dev / 96 Test 一定可构建，然后通过重复样本、偷偷改设备约束或放松标签凑数。

如果只有初始 mixed 场景能够稳定产生目标结构，先提交范围变更建议；不自动把 mixed 并入本轮纯欠压/过压协议。

## 5. 搜索和认证：避免复制现有筛选偏差

当前生成器只保留有界坐标下降找到 witness 的候选。代码也明确说明“未找到”不是不可行证明。[R4]

v3 不应继续把这一算法作为唯一入选通道。

### 5.1 建议流程

```text
固定 recipe/seed 生成候选
  → 初始潮流与状态过滤
  → 枚举 U/S/C 并保存原始覆盖结果
  → 已有模板 witness：分类 S1/S2/S3
  → 模板全部失败：搜索非模板 witness
  → 必要时对有界数量的 unresolved 候选作完整离散扫描
  → 独立磁盘重放
  → 结构证据与去重
  → 按预定规则抽取 Dev
```

S1–S3 也建议保存完整三个族的 flags，方便后续解释和验证。寻找正例可以提前成功，但声称某个族不存在解时不能提前停止其必要枚举。

### 5.2 非模板 witness 搜索

复用现有坐标搜索，同时允许确定性的多起点、成对坐标变化或其他轻量离散搜索。搜索算法不是论文必须创新的部分，不为它另造大系统。

这些搜索只负责找 witness，不负责无解证明。保持：

```text
search_unresolved ≠ physically_infeasible
```

完整离散扫描最多检查 28,561 个动作，适合用于限定数量的疑难候选、方法偏差审计或小样本精确诊断，不适合对每个初筛候选都默认展开。

禁止仅在启发式容易成功的候选上验证而隐藏其他候选。保存全部候选状态与接受率；在预先固定的小样本 unresolved 队列中作完整扫描，以量化启发式漏掉可行任务的情况。

### 5.3 性能优化与核对

可以缓存同场景同动作、复用安全的网络副本、并行不同候选。缓存键必须包括物理快照、动作、solver 配置及数值环境身份；不同场景不得共享可行性答案。

任何加速路径先与独立加载路径对照。抽样检查失败动作与成功动作，不能只检查 witness。最终选入的所有 witness 必须独立重载；必要的模板排除证据也要能重新生成。

构造阶段的 PF 数不计入 Agent 的执行成本。构造缓存、扫描结果、witness 都不得传给被测模型或在线控制 baseline。

### 5.4 默认离线资源闸门

建议配置而非硬编码：

- 首轮 scout：512 个候选，四个 recipe 默认各 128；
- 首轮最多 250,000 次实际 PF；
- 总探索最多两轮、累计最多 2,048 个候选和 2,000,000 次实际 PF；
- 全空间扫描候选默认最多 24 个，选择规则在扫描前固定；
- 并发默认保守，按本机资源配置，避免多个线程修改同一个 net；
- 所有阶段可 checkpoint，预算耗尽保存已有结果；
- 不允许运行“直到获得理想模型成功率”的无限循环。

这些数字是本方案的工程默认预算，不是已经测得的必要计算量或耗时保证。先测本机 PF 吞吐，再调整安全并发；不能为了凑齐数量自动扩大预算。

## 6. 数据规模和划分

### 6.1 目标结构

建议后续候选数据集：

| 结构 | Dev | 未来 sealed Test |
|---|---:|---:|
| S1 | 8 | 24 |
| S2 | 8 | 24 |
| S3 | 8 | 24 |
| S4 | 8 | 24 |
| 合计 | 32 | 96 |

本轮默认完成 32 Dev，不默认生成或试跑新 Test。未来在生成规则和分析定义定稿后，用独立 seed/family 生成 96 个 sealed Test；保留旧 v2 Test，不覆盖。

### 6.2 不强迫所有结构×方向全交叉

不能假定 S1–S4 在欠压、过压下都同样容易构造。

优先在有支持的类别内覆盖两种方向；保存 `structure_class × voltage_condition × recipe` 表。若某类只有过压，必须披露，不能把结构效应和欠压/过压差异混为一谈。

不机械再做 `4 结构 × 2 方向 × 3 severity` 的全配额，避免单人项目失控。severity 作为协变量保留，不作为第二套主难度等级。

### 6.3 去重与样本独立性

为物理状态计算规范化 fingerprint：忽略文件名、场景 ID、JSON 排序和日志时间，只使用真正影响物理问题的数据。

相同母样本衍生的微扰场景使用同一个 `operating_family_id`。不能跨 Dev/Test 分配同一母样本的近重复子样本。独立 seed 不能替代这一规则。

在类内按预先固定的随机规则抽样或 reservoir sampling，不按 LLM 得分挑选，也不只取候选顺序最早的样本。

Dev 的每类 8 个是独立物理场景，不是同一个网络状态改八个 ID。S4 至少来自两个不同空间 family；若无法满足，标记结构覆盖不足。

### 6.4 分布声明

这是“按动作结构分层的合成诊断集”，不是自然出现的电网工况频率估计。

必须公开：每个 recipe 的候选数、初始状态拒绝数、数值失败数、模板覆盖数、搜索 unresolved 数、各类接受数和接受率。

刻意采样 S4 本身就是条件化分布选择。规则提前固定和结果透明可以使其可研究，但不能因此声称没有任何选择偏差。

旧 v2 是开发与历史参照。若要比较 v2/v3 下的模型分数，必须统一模型/参数/协议重新评测共同参照；不能直接把旧 4096 Pilot 与新 high/16384 数据做因果前后对比。

## 7. 本轮最小成功与停止条件

### 7.1 离线原型关卡

至少确认：

- 分类与证据链正确；
- S3、S4 均有非重复、可重放的原型；
- 不是因为 solver 异常、越界或 NaN 产生“困难样本”；
- 样本仍在固定 IEEE33/4 BESS/原电压条件下；
- 算法运行成本在本地预算内。

### 7.2 完整 Dev 关卡

达到 8×4=32 个合格 Dev，完成：

- 所有 witness 独立重放；
- 全部排除模板族证据；
- family/方向/recipe/裕量表；
- 无模型参与的基线结果；
- 与旧轨道的测试回归；
- 一键复现/校验入口及费用零调用证明。

### 7.3 必须停止而不是伪完成的情形

- 两轮预算内没有足够且多样的 S4；
- S4 只能依靠未批准的物理范围修改成立；
- 所谓 S4 的模板失败主要来自求解器不稳定；
- 大量高度近重复样本被用来填满配额；
- 数值加速结果与独立 evaluator 不一致；
- 预算用尽、环境不匹配或旧工作树存在无法安全解决的冲突。

提交 `FEASIBILITY_BLOCKED` 报告，说明已生成多少、缺什么、还未证明什么。保留代码、候选和全部审计。不得自行把 S4 删除后宣称“四类完成”。

如果只有 S1–S3 可以可靠构建，可以提出“降低目标并明确三类覆盖”的备选，但作为后续研究决定，不静默替换本方案。

## 8. Agent 实验组不增加：仍然只有八组

| 编号 | 易读名称 | I | V | R |
|---|---|---:|---:|---:|
| I0-V0-R0 | 原始信息、不能预演、不能重交 | 0 | 0 | 0 |
| I1-V0-R0 | 仅领域整理 | 1 | 0 | 0 |
| I0-V1-R0 | 仅提交前验证 | 0 | 1 | 0 |
| I0-V0-R1 | 仅失败重规划 | 0 | 0 | 1 |
| I1-V1-R0 | 领域整理＋验证 | 1 | 1 | 0 |
| I1-V0-R1 | 领域整理＋重规划 | 1 | 0 | 1 |
| I0-V1-R1 | 验证＋重规划 | 0 | 1 | 1 |
| I1-V1-R1 | 全部开启 | 1 | 1 | 1 |

全因子指三个开关的全部组合，共 `2^3=8`。[E2]

新增的 S1–S4 是场景结构标签，不是四套新 Harness。同一场景交给全部八组，便于配对比较。

### 8.1 本轮不同时改预算

保持 12/4/3。不要一边换场景、一边把 preview 从 4 改 1，再声称差别来自结构。

未来研究预算 b=1/2/4，应单列实验版本和问题，不能从现有长轨迹截断后冒充“真实运行在小预算下”的结果。

### 8.2 不泄漏结构标签

被测模型不得看到：

```text
structure_class
uniform_feasible / single_feasible / coarse_feasible
template success counts
witness / witness action
search trace / feasible density / generation recipe / search budget
文件路径、隐藏 manifest 字段、构造缓存
```

场景 ID 不编码类别。不能提示“这是 S4，粗模板全无解”，否则直接把诊断答案作为策略信息送给了模型。

开发 Codex 是构造和测试代码的可信开发工具，可以读取本地 evaluator 数据做确定性构建检查；“被测 Agent 看不到”不等于阻止开发工具工作。两种角色和运行目录必须明确分离。

### 8.3 I0/I1 的解释边界

当前 I0 提供完整节点电压，I1 主要给越限节点和极值；这不是信息等价的排版实验。[R6]

本轮主矩阵不暗改其信息策略，继续解释为“原始观测 vs 当前领域摘要”的整体接口比较。尤其注意：未越限但接近边界的节点可能在摘要中缺失，这可能解释 S3/S4 上的接口效果。

不得为了让 I1 获胜，单独给它敏感度、推荐 BESS 或可行解线索。若后续要隔离“语义表示”而非信息选择，需要单独的新观测协议，不混入本轮。

### 8.4 V/R 的解释边界

V/R 既改变反馈，也改变可尝试次数。因此主矩阵估计的是当前“机制＋反馈＋机会”的整体效果，不证明相同计算预算下数值反馈本身的纯因果贡献。

V0-R1 仍可在失败 submit 后收到物理反馈；V0 不等于完全没有物理反馈。R0 不等于不会修复 JSON；协议错误处理是各组共同的运行能力。

## 9. 脚本基线：分开“模板存在”与“控制器表现”

### 9.1 本轮必须交付的受限基线

| 基线 | 作用 | 禁止使用 |
|---|---|---|
| No-action | 初始越限 sanity check | 构造结果 |
| 一次全满功率 | 简单开环参照 | 事后挑选档位 |
| 有界均匀二分 | 低成本反馈控制参照 | 预先模板枚举答案 |
| 有界局部搜索/贪心 | 同查询预算的组合搜索参照 | 事先建立的可行性缓存或 witness |

均匀二分复用现有方法，但不能宣称非线性潮流下一定具有全局单调性保证；混合越限/不收敛保留为该策略的退出原因。[R3]

局部搜索可以复用现有贪心策略加上真实查询计数，不要求为四次查询设计最优控制器。每个探测动作都必须消耗查询预算，不能先暗算八个方向再只记最优一次。

### 9.2 成本口径

与 LLM 比较时，通过一致的工具调用/计数语义运行。主对齐点可用 `V1-R0`：

```text
候选 preview 预算 ≤4
正式 submit ≤1
最终独立审计再评价 1 次（合法动作才会运行 PF）
```

分别保存：

```text
proposal_queries / preview_calls
submit_calls
online_actual_pf
audit_actual_pf
total_actual_pf
```

每局使用少于上限是正常效率差异；不能为了“公平”强行让已成功的基线继续无用查询。

### 9.3 仅作为离线参照的结果

无预算 sensitivity greedy、全空间扫描、U/S/C 覆盖率是离线参照，不与四次查询的在线控制器混成同一胜负表。构造 witness 和某贪心基线相似的搜索偏差必须保留。

“该类被定义为粗模板无解”使粗模板在 S4 上为零，这是构造定义，不是 LLM 战胜粗模板的独立证据。

## 10. 后续收费 Pilot 和 Main

这部分是后续研究计划；只有获得有效费用授权才可执行。

### 10.1 小范围连通性 smoke

从四类各随机固定一个 Dev，每个运行基础组与完整组，共 8 局。

目的只是检查模型设置、返回格式、计数和执行链，不用于推断三个因素的效果。这不是完整八组的结论实验。

### 10.2 完整 v3 Dev Pilot

```text
32 Dev × 8 条件 × 1 repeat = 256 episodes
```

同一新 run 使用相同 high/16384 和锁定协议。记录每次实际模型响应参数、完成/截断状态、完整账本和异常状态。

若需要评估重复稳定性，再按事先记录的范围追加完整配对重复；不能只重复失败案例直到成功。费用不足则停在已完成覆盖，不能把部分矩阵标作全量。

旧 192 局不能作为这里的另一个 repeat。

### 10.3 Pilot 决策不是追求某个成功率

允许以下结果：

- S4 上反馈收益更大；
- S4 上收益反而更小；
- V/R 仍高度重叠；
- 全部机制仍全成功；
- I1 由于摘要损失信息而更差；
- 存在真实、可解释的模型错误；
- 结果波动大、当前样本不足。

不因“不好看”删除场景。若 S4 确实认证成立而完整组依然全成功，只能说明该模型在当前结构范围和预算下能力足够；可预先设计一次小预算研究或收窄论文主张，不能继续无限改变分布。

若首次有效动作大量因 truncation/协议错误无法产生，先处理运行协议问题，不把它冒充物理协调失败。建议出现超过约 5% episodes 的系统性协议/传输阻断时暂停解释控制性能；该阈值是工程警戒线，不是统计显著性标准。

### 10.4 新 Test 与正式实验

生成规则、接口/输出设置和分析方案固定后，再构建独立的 96 个 sealed Test。物理构建时运行评价器认证 witness 属于数据构造，不是运行模型 Test；不向开发阶段输出模型得分。

准备新的 freeze candidate，由现有完整合同核对数据、代码、环境、任务清单、模型设置、预算和分析身份。[R5]

Main 计划保留：

```text
96 Test × 8 条件 × 3 repeats = 2304 episodes
```

结构每类 24 个场景。2304 不是 2304 个独立网络问题。正式批准、tag 和 Main 费用是独立关卡，不能由一份计划自动代替。

## 11. 指标：重点从“最终成功”扩展到“为什么需要反馈”

### 11.1 保留指标

最终成功率、最终动作合法性、首次正式提交成功率、条件恢复率、实际 PF、LLM turns、tokens、时延、实际费用估算/未知费用预留，继续使用现有统一账本。

### 11.2 必须区分首次候选与首次提交

增加或从完整事件派生：

- `first_proposal_success`：模型提出的第一个候选动作是否合格，无论它通过 preview 还是 submit 提出；
- `first_submit_success`：第一次正式提交是否合格，可能已经经历多次预演；
- `first_proposal_valid`、`no_proposal`：无动作、非法动作单列。

否则 V1 在反复 preview 后首次 submit 成功，不能称为“一次决策成功”。

第一次动作的离线额外审计是 diagnostics，不回灌模型，不计入在线查询成本。用于公平解释初次动作时，要说明模型已知道所在条件，不能把不同条件初次动作当完全同一决策。

### 11.3 机制指标

建议新增：

```text
opposite_side_violation_after_action
first_candidate_violation_magnitude
best_preview_violation_magnitude
submitted_same_as_verified_candidate
new_violation_buses
repeated_candidate_count
nonimproving_candidate_transitions
termination_reason
output_truncated / parse_error / transport_error
```

“过度校正”预先定义为：原始纯欠压情况下动作引发过压，或原始纯过压情况下动作引发欠压；与“仍有原侧越限”“双方同时越限”“非法动作/不收敛”区分。

动作 L1 可作为资源代理，但不能直接称作真实经济成本；没有全空间最优解时不能称它为最优性差距。

### 11.4 结构与裕量指标

构造/分析侧记录，不给模型：

```text
structure_class
all_full_feasible
uniform_feasible_count
single_feasible_count
coarse_feasible_count
voltage_condition
physical_severity
recipe_family / operating_family_id
witness_voltage_margin
template_evaluation_status
witness_search_method / search_pf_calls
```

可选记录采样可行密度、witness 邻域裕量、动作边界距离。采样零成功不证明无解；某个 witness 的裕量不代表全局最大裕量；某个 mixed-sign witness 不证明所有解都必须 mixed-sign。

### 11.5 观察预算曲线

从轨迹得到“第 q 次查询前是否曾找到可行候选”，可作行为描述。但它不是“把预算改为 q 时该策略会达到的成功率”，因为 Agent 知道预算后会改变行为。

若要因果比较 b=1/2/4，应真实运行冻结的小预算实验，而非事后截断原轨迹。

## 12. 分析计划和主要研究问题

### 12.1 主要问题

**RQ1：控制结构变化后，V/R 的可靠性收益是否变化？**

按 S1–S4 报告八组成功率、首次候选质量与成本。主要关注 S3/S4，而非只汇总一个总成功率。

**RQ2：V 与 R 在不同结构中是互补还是收益重叠？**

报告有无 V 时的 R 收益，再比较其差异。负的差中之差表示边际收益可能递减，不自动意味着 R 有害。

**RQ3：相同工具预算约束下，LLM 如何使用反馈，相比简单在线策略多做了什么？**

结合候选修改、过度校正、重复动作和真实 PF/模型成本回答。无预算 oracle 不能代替同预算控制器。

I 保留为预先指定的次要/探索性因素，不要求必须正收益。

### 12.2 建议主要对比

对结构 s，固定明确权重并预先登记：

```text
ΔV(s) = 对 I/R 各条件等权平均 [SR(I,V1,R,s) − SR(I,V0,R,s)]

ΔR_V0(s) = 对 I 等权平均 [SR(I,V0,R1,s) − SR(I,V0,R0,s)]

VR(s) = 对 I 等权平均 {
  [SR(I,V1,R1,s) − SR(I,V1,R0,s)]
  − [SR(I,V0,R1,s) − SR(I,V0,R0,s)]
}
```

可以把 S3/S4 的反馈效果与 S1/S2 对照作为效应异质性分析，但不能忽略方向/recipe 支持差异后声称结构具有独立因果效应。

### 12.3 推断单位

- 先核对 planned tasks 与实际记录，不能用“已经出现的 case 数”反推完整性；
- 每个场景保留全部八组及全部 repeats，按场景配对；
- bootstrap 按结构分层重采样场景，保留同场景的各组和 repeats；
- 若同一 operating family 有多个高度相关子样本，按 family 聚类，或每个 family 只保留一个代表；
- 所有失败、缺失和重试保留，分析规则预先固定；
- 给出绝对百分点差、分母和区间，不只给 p 值；
- 同时估计很多交互时明确主要/次要对比；少量单元格不支撑复杂高阶结论。

全成功单元的普通 bootstrap `[1,1]` 不代表真实成功概率为 1。必须标明该方法在未观察到失败时的局限；若提供二项区间，独立试验单位及 repeat 的聚合定义必须清晰，不把全部 episodes 当独立伯努利样本。

Logistic separation 时继续如实报告不可估计；不要添加假 p 值。可以优先用现有场景配对的绝对率差与交互对比。全因子提供组合覆盖，但不保证当前样本量有能力识别每个交互。[E2]

条件恢复率只描述“该条件下首次提交失败的人群”，不能跨条件直接当作同一随机化人群的纯因果效果。

### 12.4 合成均衡集的总分

四类等额时，可以报告四类等权 macro average；不能解释为自然电网工况下的期望成功率。必须同时给出分层结果。

每层 Test 24 个独立场景仍然有限，不应因为三次 repeats 就声称样本量变成 72 个独立场景。效应不确定时报告不确定，不为显著性挑子集。

## 13. 一个推荐但非本轮默认执行的补充控制

若之后要把论文主张从“整套 Harness 有用”推进到“定量物理反馈比只有成功/失败更有用”，建议只增加一个明确的匹配预算补充实验：

```text
固定 I0、V0、R1
最多 3 次 submit
共同的合法性/协议错误处理

组 A：失败后给现有完整数值反馈
组 B：失败后只给成功/失败与剩余机会，不给节点、电压、幅度
```

两组均在首次成功后终止，其最大尝试数相同，但实际尝试数可不同。组 B 不是完全无信息——失败本身就是信息。

新组须有单独条件 ID、版本与费用授权，不能混成原 I/V/R 的第九种组合。主矩阵的完整反馈组在严格相同设置、样本、重复和执行安排下才可作对照。

这比同时增加 SOC、多 Agent 和更多模型更直接地回应“收益是否只是因为多试了几次”的问题。但本轮先完成结构集；不擅自启动这一付费补充。

当前 `load_manifest()` 将 `ieee33-bess-voltage-v1` 当作加载/物理 schema 标识，不能仅为把数据集叫 v3 而修改字符串并破坏兼容。[R6]

显式区分并哈希：

```text
physical_schema_version
corpus_version = structure-v3
generator_version
structure_definition_version
observation_protocol_version
dataset_sha256
```

可以保留现有物理 schema，新增 corpus/结构定义字段；manifest 与 freeze 合同必须包含实际使用的版本和模板定义身份。旧结果保持原身份，不能回填新版本。

## 15. 必须覆盖的测试

### 15.1 结构逻辑

用 mock evaluator 的人工可行集合分别构造 S1/S2/S3/S4、全无解、未评完、数值异常，验证：

- 动作网格 28,561；
- U/S/C 数量 13/49/81、并集 131；
- 排除规则与优先级；
- 正负动作均被覆盖；
- S4 不能仅凭一个非均匀 witness 得出；
- 悬而未决不能变成 S4；
- seed 和排序不改变同物理状态的类别。

### 15.2 物理与证据

所有入选 witness 独立重放；必要的族排除证据可再现；加速/缓存与独立 evaluator 一致；修改物理文件、模板定义、solver 或证据应触发完整性错误。

S4 的阳性物理集成测试必须用实际生成并认证的 Dev 样本，不能用 mock 测试冒充真实 S4 已存在。

### 15.3 运行与隔离

八条件日志无结构标签/witness；baseline 不读模板缓存；无 API key 下离线工作通过；预算耗尽可恢复且不重复 PF 记账；Test 未授权被拒绝；新模型设置不得续写旧 run。

### 15.4 数值状态

检查应评价节点均存在、在役、有限，非收敛/异常不伪装为零越限。不要为提高分数自动放宽成功容差。

witness 最小电压裕量记录为：

```text
min_i min(V_i - 0.95, 1.05 - V_i)
```

裕量非常小时单列 fragile 标记，进行独立重放稳定性检查。本轮不私自新增裕量阈值作为隐藏成功判据；如引入统一的数据质量接受阈值，必须提前写入生成协议并报告接受率变化。

## 18. 最终给用户的报告格式

最终中文回复先用一小段说明：

```text
状态：PASS / FEASIBILITY_BLOCKED / INCOMPLETE
已完成到：B?
是否调用模型API：否/若另获授权则明确次数与账本

```

然后给出：

1. 当前源 commit / 相关改动文件 / 新文档路径；
2. 各 recipe 的候选数、接受/拒绝/unresolved 分布、实际 PF 次数；
3. S1/S2/S3/S4 场景数、方向/family 交叉表、去重结果；
4. S4 的证据：模板全覆盖、非模板 witness、独立重放、数值状态；
5. 各在线基线的成功率、查询数及审计成本分离；
6. 实际执行的测试命令与结果，不把已有文档里的“92 passed”当本次新测试；
7. 一次命令复现/继续的方式；
8. 是否值得进入 v3 Dev Pilot，以及还缺哪些证据。

PASS 不意味着可以投稿或自动启动 Main；它只表示结构升级和离线验收达到本方案标准。

## 19. 预期论文定位与边界

工作题目可暂定：

> Structure-aware Evaluation of Verification and Recovery in Power-System LLM Agents  
> 面向不同控制结构的电力系统大模型智能体验证与恢复机制评估

希望形成的贡献：

- 给出基于预定义动作族、具有正反证据的场景结构分类；
- 区分物理严重度、模板覆盖、真实在线查询成本和模型表现；
- 在同一 I/V/R 矩阵下评价反馈收益的结构差异；
- 以首次候选、过度校正、反馈修正和成本解释结果，而不仅是报最终成功率。

不得预先声称方法“首次提出”“普遍优于传统控制”或“一定达到投稿要求”；创新性仍需对相关工作进行专门核查。

这仍是静态、低维、单拓扑上的受控合成评测。S4 不是长期 Agent 规划；通过 benchmark 不代表真实储能设备运行安全。若后续所有结构仍被很短的反馈循环覆盖，应如实收窄主张，而不是反复出题直到模型失败。

**路线 B 的成功，是使研究结论有更清楚的适用范围和证据，不是使曲线符合预想。**
