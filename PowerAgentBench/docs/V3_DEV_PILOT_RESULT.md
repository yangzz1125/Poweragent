> 日期：2026-10-02。按 [V3_PILOT_PREREGISTRATION.md](V3_PILOT_PREREGISTRATION.md) 执行。这是 Dev 开发诊断，不是论文 Test 结论；每个结构层只有 8 个场景，区间较宽。

## 1. 运行

- 32 个 Dev 场景 × 8 个条件 × 1 次 = 256 局，全部 `complete`，无出错局。
- 模型 DeepSeek `deepseek-flash`，Responses 接口，`--max-output-tokens 16384`，`--reasoning-effort high`。
- 费用（账本）：已计费 ¥10.18；26 个未知用量请求按每个 ¥0.20 预留共 ¥5.20；合计占用 ¥15.38，上限 ¥22。账本中有 2 个悬空请求，均已有用户批准的预留。
- 4 局触发单局费用上限，17 局发生过 API 重试。
- 运行经过多次暂停与续跑（内存不足被系统终止、高峰时段暂停）。续跑前两次手工更新了运行身份：`code_commit`，以及节假日低谷价改动后的 `code_commit`、`source_sha256`、`pricing_sha256`（见第 6 节）。

## 4. 天花板判定（预登记第 7 节）

不成立。规则 1 要求所有 V1 条件及两个 V0-R1 条件在 S3∪S4 上都 ≥95%，实际为 62.5%–81.3%，仅 I0-V1-R1 为 100%。规则 2 要求 `dV` 区间包含 0 且点估计绝对值 <0.05，S3、S4 的 `dV` 均明显大于 0。因此**不启用**小预算实验。

## 5. 协议阻断检查（预登记第 8 节）

预登记写的是“由输出截断、解析失败或传输错误造成的无效局超过 5%”，没有说明“造成”如何计数，这里给出两个口径，**结论取决于口径**：

| 口径 | 局数 | 占比 |
|---|---|---|
| 出现过解析错误或输出截断的局（解析错误 19，截断 10，无重叠） | 29/256 | 11.3% |
| 其中最终失败的局 | 12/256 | 4.7% |
| 传输错误造成的无效局 | 0 | 0% |

- 按“最终失败”口径低于 5%，按“出现过”口径高于 5%。5% 是工程警戒线，不是统计标准。
- 29 局中 D0007、D0021、D0026 各 4 局，共 12 局，集中度高。
- 账本里有 24 个 error 事件（2518 次请求中），26 个未知用量请求，连接层错误未找到根因。
- 因此：不据此排除任何局，对比结果照实保留；协议问题（尤其这三个场景的解析/截断）列为待处理项。

## 6. 方法偏差，须在引用本结果时一并说明

1. **运行身份的手工更新。** 中途因提交号变化手工改了 `run.json` 的 `code_commit`（备份 `run.json.bak_before_commit_update`）。随后因节假日按低谷价的改动（提交 `31eb23a`），又更新了 `run.json` 的 `code_commit`、`source_sha256`、`pricing_sha256`，以及 `campaign.json` 的 `pricing_sha256`（均有 `.bak_before_holiday_update` 备份）。
2. **节假日按低谷价。** 依据是 DeepSeek 定价页（2026-10-02 读取）：周末和中国法定节假日全天为空闲时段。`pricing.json` 增加 `holidays: [2026-10-01, 2026-10-02, 2026-10-03]`。此前计费的请求都发生在非节假日，成本核算不受影响。
3. **悬空请求。** 两个悬空请求共 ¥0.40 的预留已由用户批准；它们是预留，不是确认的实际费用。
4. 内存不足造成两次被动中断，续跑沿用同一输出目录和同一运行 ID。
