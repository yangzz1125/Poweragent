# Dev结构覆盖审查：多数case不需要细粒度协调

## 协议与数据范围

全24个v2 Dev，未筛选case，不读Test成绩、不调用LLM、不修改场景或成功标准。脚本 `scripts/study_voltage_shortcuts.py` 先保存protocol，再执行：

- 均匀二分策略：根据初始纯欠压/过压确定符号，对0.25–1.50 MW共6档作floor-midpoint二分；最多4次PF查询，根据剩余欠压/过压缩小区间，遇到两侧同时越限或不收敛停止。执行时不知道模板枚举结果，不使用witness。
- 单次全满功率：四台全部按正确方向±1.5 MW。
- 均匀模板：12个非零公共功率值（含正负方向）。
- 单台模板：每次只有一台非零，遍历4台×12档。
- 零/满功率组合：每台取{-1.5,0,+1.5}，穷举3^4=81组合。

每个动作由独立evaluator重载冻结网络评分，同一case重复动作缓存用于减少审查成本。二分策略的查询次数单独记录，最终动作再独立重放。共3168次实际PF。模板覆盖率是穷举后知道“存在某个模板”，不是一个同等预算的控制器成功率。

结果目录：`E:/work/voltage_shortcuts_dev_v2`。公开汇总在 `research_records/voltage_control/dev_structural_coverage/`；未公开私有策略动作trace或任何witness。

## 结果

| 诊断项 | 覆盖/成功 |
|---|---:|
| 一次全满功率（符号由越限方向决定） | 8/24 |
| 均匀模板中存在解 | 19/24 |
| 最多4查询的均匀二分策略 | 19/24 |
| 单台BESS模板中存在解 | 7/24 |
| 81个零/满功率组合中存在解 | **24/24** |

均匀二分策略实际最多用了3次查询；成功19局平均1.84次、失败5局平均2.60次，总平均2次。它的独立最终重评另算1次。若接入与LLM相同的preview→submit→最终评分流程，还需计正式submit的PF，不能直接把这个独立脚本的总成本与LLM Harness总成本相减。

按预定优先级得到互斥结构标签（另保留所有原始覆盖flags）：

| 首个满足的结构类别 | 数量 |
|---|---:|
| 正确方向全满功率即成功 | 8 |
| 不全满功率，但均匀中间档存在解 | 11 |
| 无均匀解，但只调一台BESS存在解 | 4 |
| 以上均无解，但零/满功率多台组合有解 | 1 |
| 超出所有已测试模板族 | 0 |

非均匀5局中，D0014/D0016/D0018/D0019可用单台调节解决；只有D0022同时超出均匀/单台模板族，但仍有7个零/满功率组合可行。不要把“非均匀”直接等同“复杂多设备协调”。

## 对任务难度的结论

结合前轮的可行密度研究：本任务不是随便调都成功，也确实有极窄的物理可行区域；但**解的结构往往简单**。4维、每台13档的表面动作空间较大，并不代表每个case都需要搜索这个全空间。

最直接的盲点：当前24个Dev都不强制要求使用细粒度中间功率组合，因为至少存在一个三档粗模板解。知道该选哪个设备/哪个模板仍需信息和控制判断，穷举81次也不符合LLM的4-preview限制，所以不能说任务“毫无推理要求”。但若主张复杂协调/长期Agent规划，当前证据明显不足。

原severity=hard的8个case中，5个属于全满功率即可解决，2个均匀中间档即可解决，仅1个超出均匀/单台模板。这解释了部分Hard任务比Easy更容易被LLM一次猜中的现象。

## 后续分布设计建议（不立即修改v2）

如果选择继续研究当前短程物理反馈任务，可以直接收窄论文主张并如实报告天花板，不必强行制造难度。

如果要提升对Harness差异的辨别能力，应先在新的Dev候选池预登记结构覆盖目标，再生成独立版本：

1. 保留一部分明确的边界/均匀可解场景作基础能力层。
2. 增加设备位置选择、非均匀幅度和同时两侧约束的代表性，但保持原4-BESS控制空间和电压成功标准。
3. 将“至少存在内部功率witness”“是否存在均匀/单台/粗模板解”作为**公开定义的物理结构指标**，不依据任何LLM的成功/失败筛选。
4. 若为了研究协调控制而显式构造不存在粗模板解的层级，必须说明这是一种受控合成分布，并公布候选接受率；不能伪称一般现实任务分布或事后只留baseline失败case。
5. severity另列为协变量，不用它直接命名控制难度。欠压/过压分别覆盖各结构，不把初始mixed场景悄悄加入原协议。
6. v2和全部Pilot保留为开发依据；Test未冻结前才能确定新分布；不对现有Test试分数后再决定改动。

当前不建议花预算跑2304次Main。应先确定研究主张：验证简短反馈循环的可靠性，还是比较具有非平凡协调要求的Harness。两者都可研究，但不能用当前结果替后者背书。
